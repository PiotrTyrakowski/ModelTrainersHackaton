# Tiny Qwen baseline — 26 September 2026

**3/60 points (5%), provisional local grading.** This is a measured baseline for
the exam-solving system, not a passing result. It ran on the complete 2023
practice paper: 37 questions, including the images and essay. No grading is left
pending. This paper has already been inspected during development and is not an
untouched evaluation set.

| Measurement | Result |
|---|---|
| Model | Qwen3.5:0.8b, unchanged weights, Q8_0 |
| Learned files, including vision | 1,036,034,688 bytes |
| Solver | Direct answer; no retrieval, tools or essay bank |
| Runtime | Local Apple M5, Metal, Ollama 0.34.4 |
| Questions processed | 37/37 |
| Valid answer objects | 33/37 |
| Total question time | 317.49 seconds — 5 minutes 17 seconds |
| Model calls | 37 |
| Prompt / output tokens | 65,881 / 17,771 |
| Cloud inference charges | None; inference ran locally |

The model received each question and its supplied sources/images. Answer keys
and official marking rubrics were kept outside the solver context. Closed
answers were scored by the existing grader; 28 remaining successful answers
received a conservative Codex rubric review, including one prose multiple-choice
answer the automatic parser could not resolve. These are provisional grades,
not an official examiner assessment. No official passing threshold is assumed.

All earned points came from two true/false questions. This does not establish
reliable historical reasoning. The model invented names and dates, misread
visual evidence, and often paraphrased the question instead of solving it.

Questions 4.2, 10, 20 and 26 hit the 2,200-token output cap while repeating text;
their JSON was incomplete. The exporter therefore produced four blank answers.
Those items carry **19 possible points**, but repairing formatting would not
automatically recover them: the raw text also contains substantial factual
errors. The essay mixed the three available topics and used rulers from the
wrong centuries. Increasing the output cap alone is not justified by this run.

Question 16.1 illustrates a separate failure: a correct yes/no conclusion earned
zero because the required justification was missing from the submitted answer.
Question 11.1 received a conservative zero because its account of liberum veto
was historically confused; an examiner may assess borderline answers differently.

## Decision for the next checkpoint

1. Test a shorter answer contract with bounded evidence and explicit completion
   of required parts. Keep this model and paper unchanged. Success means fewer
   invalid outputs **and** more rubric points, not merely valid JSON.
2. Then compare factual retrieval against that baseline. Add source material to
   address observed knowledge gaps, keeping exam solutions out of the corpus.
3. Evaluate essay retrieval as its own implementation once relevant essays exist.
   The current two demonstration essays do not cover this paper's topics; do not
   force a nearest match.

Model changes should get a separate comparison. The user prioritizes a small
passing system; this 0.8B baseline should not lock the research into a model that
cannot use the available evidence. Confirm any gains on an untouched paper later.

## Evidence and reproduction

The [machine-readable summary](2026-09-26-qwen35-direct.json) includes per-item
grades, reasons, model identity, input fingerprints and artifact hashes. Complete
raw answers, separate grades, the valid submission-shaped export, and live
runtime verification remain locally under
`artifacts/checkpoints/qwen35-direct-local-v1/`. They are ignored by Git.

Follow [the checkpoint workflow](../checkpoints.md). It currently needs the
adjacent `matura-lab` evaluator and local exam assets; this repository alone does
not include that evaluator or the source PDFs. The checkpoint freezes their
hashes and rejects changes during a run.

Validation: 11 checkpoint accounting tests passed; all 37 export IDs validated,
with the four failed generations preserved as blanks. Software validation does
not change the measured 3/60 score.
